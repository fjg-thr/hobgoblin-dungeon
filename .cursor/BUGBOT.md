# Cursor Bugbot Review Guide

Use this file as repository-specific context when reviewing pull requests for the Hobgoblin Ruin prototype.

## Deployment boundary

- This file supplies review guidance only. Hosted Cursor Bugbot must still be enabled outside the repository through the Cursor dashboard, Cursor GitHub App repository access, Bugbot Admin API credentials, or equivalent live service configuration.
- Treat a merged copy of this file on the default branch as the source of repo-specific Bugbot guidance. PRs that add or edit this file may not be reviewed with the updated guidance until after merge.
- Manual smoke triggers are top-level PR comments: `cursor review` or `bugbot run`.
- For diagnostics, use `cursor review verbose=true` or `bugbot run verbose=true` to request detailed status, request IDs, and troubleshooting output.
- If you cannot inspect the hosted Bugbot installation, state that repository files can provide review context but cannot prove managed Bugbot enablement.

## Review priorities

- Prioritize concrete correctness issues, regressions, missing verification, asset path mismatches, accessibility gaps in DOM UI, gameplay-state bugs, and deployment risks.
- Avoid blocking on broad style preferences unless they cause maintenance or user-facing problems.
- Prefer findings that cite the exact changed file and runtime behavior affected.
- When a PR touches generated assets or manifests, verify both the source-generation path and the runtime-loading path.

## Project map

- App shell and metadata: `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`.
- React/Phaser bridge: `src/game/GameCanvas.tsx`.
- Main game scene: `src/game/scenes/DungeonScene.ts`.
- Dungeon layout data: `src/game/maps/startingDungeon.ts`.
- Runtime asset manifest: `src/game/assets/manifest.ts`.
- Public assets: `public/assets/**` and `public/opengraph-image.png`.
- Asset and audio tooling: `tools/**` and `scripts/generate-retro-soundtrack.mjs`.
- Package managers: both `package-lock.json` and `pnpm-lock.yaml` are tracked; dependency work should keep them intentionally in sync.

## Gameplay and input checks

- Runtime firing currently uses `Space` and pointer/click firing. README also mentions `J`; only flag that mismatch for control-doc or input PRs, not unrelated changes.
- The Phaser title screen and how-to-play modal have responsive compact and tiny viewport branches. Review changes for broken close behavior, unreadable compact layout, incorrect hit zones, and stale control copy.
- Initial goblins are seeded from `dungeon.enemyStarts`. Additional goblins ramp with target enemy count, and brutes unlock through `BRUTE_UNLOCK_KILLS` / `BRUTE_UNLOCK_MS`; do not assume all enemies are progression gated.
- Power-up spawn weights, unlock gates, and presentation metadata live in `POWERUP_CONFIG`. Durations and effects live in nearby constants and collection logic, and blast uses `blastShotReady`.
- README documents regular ammo, hearts, quickshot, haste, ward, and blast. Code-defined seeker ammo exists separately; review seeker changes against code behavior as well as docs when relevant.
- Review collision, camera, world bounds, depth sorting, projectile cleanup, pickup cleanup, and scene restart paths for leaks or stale state.

## Asset, audio, and metadata checks

- `src/game/assets/manifest.ts` is the runtime audio and asset source of truth for what `DungeonScene` loads.
- `public/assets/audio/audio-manifest.json` is auxiliary and should stay consistent when audio inventories change.
- Procedural sound effects are generated by `tools/generate_audio_sfx.mjs`.
- The retro soundtrack is generated by `scripts/generate-retro-soundtrack.mjs`.
- Corporate goblin and spreadsheet brute processing use `python3 tools/process_corporate_goblin_assets.py` and `python3 tools/process_spreadsheet_brute_assets.py` when those assets are touched.
- Metadata in `src/app/layout.tsx` references `/opengraph-image.png`; changes to share metadata should keep the public image, dimensions, and alt text aligned.
- For sprite-sheet PRs, check PNG/JSON frame names, dimensions, animation frame references, nearest-neighbor expectations, and manifest paths together.

## UI and accessibility checks

- This repo does not currently configure Tailwind. DOM UI should follow existing semantic HTML and `src/app/globals.css` patterns unless a PR intentionally adds a styling system.
- Review Phaser canvas overlays separately from DOM accessibility. Check pointer zones, keyboard/mouse affordances, visible states, responsive placement, and limitations caused by canvas-rendered text.
- If a PR adds interactive DOM elements, require semantic controls, accessible names, keyboard operation, focus visibility, and responsive behavior.

## Verification expectations

- For source changes, prefer:
  - `npm run build`
  - `npx tsc --noEmit --incremental false`
- `next lint` is not reliable in this Next 16 project unless the PR explicitly fixes the lint setup.
- `npm run build` can rewrite `next-env.d.ts`; restore it unless the PR intentionally changes generated Next typing behavior.
- Plain `npx tsc --noEmit` can create `tsconfig.tsbuildinfo` because `incremental` is enabled. Prefer `--incremental false` and remove generated artifacts if they appear.
- For dependency PRs, verify the relevant npm and pnpm lockfiles instead of updating only one ecosystem.

## Missing tests and risk notes

- The project is mostly build-verified rather than unit-tested. For meaningful gameplay changes, request manual smoke coverage: start screen, how-to-play modal, movement, firing, ammo pickups, hearts, power-ups, enemy spawning, game over, restart, mute toggle, and compact viewport behavior.
- For asset-heavy PRs, request evidence that changed assets were regenerated or inspected and that runtime loading was exercised.
- For hosted Bugbot rollout PRs, confirm outside-repo setup separately: Cursor dashboard/org settings, GitHub App repository access, desired automatic or manual trigger mode, optional required status check, and a PR review smoke test when credentials are available.
