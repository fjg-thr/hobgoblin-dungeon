# Cursor Bugbot Review Guide

Use this file as the repository-level context for Cursor Bugbot reviews of Hobgoblin Ruin Prototype, a Next.js, React, TypeScript, and Phaser 4 web game.

## Review priorities

- Prioritize regressions that affect runtime gameplay, browser boot, rendering, input, asset loading, scoring, health, powerups, audio, and production builds.
- Treat `src/game/scenes/DungeonScene.ts` as the main gameplay surface. Review Phaser scene lifecycle changes carefully: preload/create/update ordering, timer cleanup, event listener cleanup, camera resizing, tweens, and object destruction.
- Treat `src/game/assets/manifest.ts`, `public/assets/**/*.json`, and generated PNG/WAV assets as tightly coupled. Flag missing manifest entries, mismatched frame names, changed dimensions without matching metadata, or paths that will 404 at runtime.
- Keep TypeScript strict. Prefer explicit interfaces for shared data shapes, avoid `any`, and preserve the `@/*` path alias.
- The app is intentionally client-heavy. `src/game/GameCanvas.tsx` should keep Phaser behind dynamic client-side imports and should destroy the game instance on React cleanup.
- For UI and app-shell changes, follow existing semantic HTML and `src/app/globals.css` patterns. This repo does not currently use Tailwind or Shadcn.

## Existing project constraints

- This is a prototype, but production build regressions still matter. Use `npm run build` and `npx tsc --noEmit` as the baseline checks when relevant.
- `npm run lint` currently maps to removed `next lint` behavior for this Next version. Do not treat it as a baseline check unless the PR intentionally updates lint tooling and script configuration.
- `next-env.d.ts` and `.next` output may be regenerated by Next commands. Do not request generated type/output diffs unless the PR intentionally changes Next tooling behavior.
- `tsconfig.tsbuildinfo`, `.next/`, `node_modules/`, generated local env files, and processed build output should stay untracked.
- Avoid broad dependency or lockfile churn unless the PR is explicitly about dependencies or tooling.

## Gameplay context to avoid noisy findings

- README and code currently differ in a few known areas. Do not block unrelated PRs solely for these existing mismatches:
  - README says `Space` or `J` fires; current gameplay reliably supports `Space` plus pointer/click firing.
  - Seeker ammo exists in code after progression milestones but is not fully documented in README.
  - README describes blast as rare late-game, while code currently unlocks it earlier via `POWERUP_CONFIG.blast`.
- If a PR touches these specific systems or docs, do review whether the change should reconcile the mismatch.
- Combat is intentionally simple: finite ammo, close-range enemy attacks, contact damage unless ward is active, kill/time gated pickups, and prototype collision checks.

## Asset and tooling guidance

- Asset processors and generators live under both `tools/` and `scripts/`. Review generated-asset PRs by checking that source prompts, processors, manifests, JSON frame metadata, and runtime references remain consistent.
- Preserve nearest-neighbor/pixel-art assumptions. Flag changes that introduce smoothing, fractional frame dimensions, or asset scaling that would blur sprites unless intentional.
- Large binary asset changes are acceptable for this game, but they should be paired with the metadata or manifest changes needed to load them.

## Cursor Bugbot deployment notes

- The root `.cursor/BUGBOT.md` file is always included by Bugbot and supplies repository-specific review context.
- Managed Bugbot enablement is external to this repo. Confirm in the Cursor dashboard that the GitHub integration has access to `fjg-thr/hobgoblin-dungeon`, Bugbot is enabled for the repository, and the desired trigger mode is selected.
- If dashboard or Admin API access is unavailable, report that this repository file provides review context but cannot by itself prove the managed Bugbot service is enabled.
- After external enablement, verify with a PR smoke check that the `Cursor Bugbot` review/check appears and respects these project rules.
