# Cursor Bugbot review guide

Use this file as repository-specific context when reviewing PRs for the
Hobgoblin Ruin prototype. This guide improves Bugbot's review signal, but it
does not by itself prove that the managed Cursor Bugbot service is enabled for
the repo. Managed enablement still depends on Cursor dashboard or org settings,
GitHub App repository access, optional Admin API credentials, and a live PR
review smoke check after this file is available on the default branch.

## Project shape

- App shell: `src/app/layout.tsx`, `src/app/page.tsx`, and
  `src/app/globals.css`.
- Client Phaser bootstrapping: `src/game/GameCanvas.tsx`.
- Gameplay, HUD, audio, input, powerups, enemies, combat, scene cleanup, and
  runtime asset loading: `src/game/scenes/DungeonScene.ts`.
- Dungeon generation and tile semantics: `src/game/maps/startingDungeon.ts`.
- Runtime asset source of truth: `src/game/assets/manifest.ts`.
- Static assets: `public/assets/**`.
- Asset/audio tooling: `tools/process_assets.py`,
  `tools/process_actor_death_assets.mjs`,
  `tools/process_combat_juice_assets.mjs`,
  `tools/process_corporate_goblin_assets.py`,
  `tools/process_gpt_tile_powerup_assets.mjs`,
  `tools/process_pickup_intent_effect_assets.mjs`,
  `tools/process_spreadsheet_brute_assets.py`,
  `tools/generate_powerup_sprites.mjs`,
  `tools/generate_polish_sprites.mjs`,
  `tools/generate_brute_ammo_sprites.mjs`,
  `tools/generate_audio_sfx.mjs`, and
  `scripts/generate-retro-soundtrack.mjs`.

## Managed Bugbot expectations

- Review PRs for behavior regressions, missed cleanup, broken assets, and
  missing verification before style preferences.
- For manual GitHub PR triggers, top-level comments can use `cursor review` or
  `bugbot run`; diagnostic runs can use `cursor review verbose=true` or
  `bugbot run verbose=true` to surface request IDs and log details.
- Do not claim service enablement from this file alone. If asked to prove
  deployment, require a merged default-branch guide plus Cursor/GitHub App
  configuration or a real PR review smoke check.
- New or changed guidance may not affect the same PR until the file is merged
  to the default branch and Bugbot reloads repository context.

## Review priorities

### Next.js and React shell

- `GameCanvas` is a client component and dynamically imports Phaser. Guard
  against SSR-only API use, duplicate Phaser game creation, and missing
  `destroy(true)` cleanup on unmount.
- `next-env.d.ts` is generated by Next. Avoid treating route-type rewrites from
  local `next dev` or `next build` runs as intentional source changes unless
  the PR is explicitly about Next generated typing behavior.
- This repo currently has no Tailwind or shadcn setup. For DOM UI changes, use
  semantic HTML and the existing CSS patterns in `src/app/globals.css` unless a
  PR intentionally introduces a design system.

### Phaser scene lifecycle and input

- Check new scene listeners, keyboard handlers, timers, tweens, and input zones
  for cleanup during `SHUTDOWN` or object destruction.
- Runtime keyboard firing is bound to `SPACE`; pointer/click firing is handled
  with Phaser pointer events. README also mentions `J`, which is an existing
  documentation/runtime mismatch. Flag PRs that worsen or claim to fix controls
  without updating both code and docs, but do not block unrelated PRs solely for
  that baseline mismatch.
- Review pointer zones such as the mute button for hit area placement,
  responsive scaling, cursor feedback, and behavior after resize.
- Canvas-heavy UI cannot use normal DOM accessibility for in-game controls, so
  look for practical alternatives: clear visible affordances, keyboard parity
  where feasible, readable text contrast, and no pointer-only critical flow
  unless intentionally scoped.

### Gameplay and combat

- Preserve tile/world coordinate conversion invariants and collision semantics
  when touching movement, projectiles, enemy pathing, props, or map generation.
- Powerups are code-defined in `POWERUP_CONFIG`: quickshot is immediate, haste
  unlocks after early progress, ward is later and rare, and blast currently
  unlocks at 2 kills or 16 seconds. README calls blast late-game, so treat that
  as a baseline docs/code mismatch unless the PR intentionally fixes it.
- Seeker ammo/projectiles exist in code, unlock after progression thresholds,
  and are omitted from README controls. Review seeker changes against runtime
  behavior, and require docs updates only when the PR changes player-facing ammo
  behavior or claims documentation coverage.
- Watch pooled or transient visuals such as projectiles, death sprites, combat
  effects, damage numbers, hit stop, camera shake, and pickup intent effects for
  leaked objects, stale references, or unbounded growth.
- Check audio changes against the scene-level mute toggle and persisted mute
  preference. Runtime audio is loaded from `assetManifest.audio`, not from
  `public/assets/audio/audio-manifest.json`.

### Assets and generated files

- Asset manifest entries must match files under `public/assets/**`, including
  frame sizes and metadata paths used by Phaser spritesheets.
- When generated sprite/audio artifacts are changed, look for the matching
  source/tooling update or a clear explanation of the generated provenance.
- Use exact generator commands instead of wildcard script names when suggesting
  verification:
  - `npm run process:assets`
  - `npm run process:death-assets`
  - `npm run process:combat-juice`
  - `npm run generate:powerups`
  - `npm run generate:combat-assets`
  - `node tools/process_gpt_tile_powerup_assets.mjs`
  - `node tools/process_pickup_intent_effect_assets.mjs`
  - `python3 tools/process_corporate_goblin_assets.py`
  - `python3 tools/process_spreadsheet_brute_assets.py`
  - `node tools/generate_polish_sprites.mjs`
  - `node tools/generate_audio_sfx.mjs`
  - `node scripts/generate-retro-soundtrack.mjs`

### Metadata and public files

- `src/app/layout.tsx` references `/opengraph-image.png`, which is currently
  absent from the repository. Treat this as a baseline gap. Block PRs that
  introduce or worsen broken public metadata references, remove referenced
  assets, or claim to fix metadata without adding the asset.

### Dependencies and tooling

- `package.json` uses latest Next/React/TypeScript ranges and pins Phaser to
  `4.0.0-rc.4`. Do not recommend changing Phaser unless the PR intentionally
  addresses Phaser compatibility.
- Both `package-lock.json` and `pnpm-lock.yaml` are tracked. Dependency PRs
  should keep the relevant lockfiles consistent and verify the package manager
  they changed.
- `next lint` is not reliable with current Next versions in this repo. Prefer
  `npm run build` and `npx tsc --noEmit --incremental false` for source changes.

## Suggested verification by change type

- Markdown-only Bugbot guide change:
  `git diff --check origin/main...HEAD`
- TypeScript, React, Phaser, or asset manifest source change:
  `npx tsc --noEmit --incremental false` and `npm run build`
- Gameplay/input/HUD/audio change: run the app with `npm run dev` and smoke
  test movement, Space firing, click firing, pickup collection, mute toggle,
  resize behavior, game over/restart, and F3 debug overlay when relevant.
- Asset generation change: run the exact generator or processor command that
  owns the changed artifact, then verify the manifest and generated dimensions.
- Dependency change: run install/audit/build commands for the touched lockfile
  ecosystem and note any known baseline audit limitations separately from new
  vulnerabilities.
