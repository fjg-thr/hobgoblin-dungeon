# Cursor Bugbot review guide

Use this as repo-specific context for Hobgoblin Ruin PR reviews. This file does
not prove the managed Cursor Bugbot service is enabled; proof still requires
Cursor/GitHub App configuration or a live PR review smoke check after merge.

## Project map

- Next shell: `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/globals.css`.
- Phaser boot: `src/game/GameCanvas.tsx`; scene:
  `src/game/scenes/DungeonScene.ts`.
- Dungeon generation: `src/game/maps/startingDungeon.ts`.
- Runtime asset source of truth: `src/game/assets/manifest.ts`.
- Static assets: `public/assets/**`; metadata assets belong at `public/` root.
- Asset/audio tooling: `tools/**` and `scripts/generate-retro-soundtrack.mjs`.

## Managed Bugbot expectations

- Prioritize behavior regressions, leaked Phaser objects/listeners, broken
  assets, and missing verification before style preferences.
- Manual GitHub PR triggers: `cursor review` or `bugbot run`; diagnostics:
  `cursor review verbose=true` or `bugbot run verbose=true`.
- New guidance may not affect the same PR until merged and reloaded by Bugbot.

## Review priorities

### Next.js and React shell

- `GameCanvas` dynamically imports Phaser; check for SSR-only API use, duplicate
  game creation, and missing `destroy(true)` cleanup.
- `next-env.d.ts` is generated by Next. Do not treat route-type rewrites from
  `next dev` or `next build` as intentional unless the PR is about that.
- No Tailwind/shadcn setup exists. DOM UI should use semantic HTML and existing
  CSS unless a PR intentionally adds a design system.

### Phaser lifecycle, input, and UI

- New listeners, keyboard handlers, timers, tweens, and input zones need cleanup
  during `SHUTDOWN` or object destruction.
- Runtime keyboard firing is `SPACE`; pointer/click firing uses Phaser pointer
  events. README also mentions `J`, a baseline mismatch. Flag PRs that worsen
  or claim to fix controls without updating both code and docs.
- Review pointer zones such as the mute button for hit area, scaling, cursor
  feedback, and resize behavior.
- Canvas UI cannot use normal DOM accessibility. Look for affordances, keyboard
  parity where feasible, readable contrast, and no pointer-only critical flow.

### Gameplay, combat, and audio

- Preserve tile/world coordinate conversion and collision semantics when
  touching movement, projectiles, enemy pathing, props, or map generation.
- `POWERUP_CONFIG` defines runtime powerups; blast currently unlocks at 2 kills
  or 16 seconds while README calls it late-game. Treat as a baseline mismatch
  unless the PR intentionally fixes it.
- Seeker ammo/projectiles exist in code and are omitted from README controls.
  Require docs updates when PRs change player-facing ammo behavior.
- Watch transient/pooled visuals (projectiles, deaths, combat effects, damage
  numbers, hit stop, camera shake, pickup intent effects) for leaks.
- Runtime audio loads from `assetManifest.audio`; check changes against the mute
  toggle and persisted mute preference.

### Assets, metadata, and generated files

- Manifest entries must match `public/assets/**`, including Phaser frame sizes
  and metadata paths.
- Generated sprite/audio changes need matching source/tooling updates or
  provenance.
- `src/app/layout.tsx` references `/opengraph-image.png`, but this branch does
  not track `public/opengraph-image.png`. Treat as baseline for unrelated PRs;
  block share-metadata PRs that do not add/fix the asset and metadata together.
- Prefer exact generator commands:
  `npm run process:assets`, `npm run process:death-assets`,
  `npm run process:combat-juice`, `npm run generate:powerups`,
  `npm run generate:combat-assets`,
  `node tools/process_gpt_tile_powerup_assets.mjs`,
  `node tools/process_pickup_intent_effect_assets.mjs`,
  `python3 tools/process_corporate_goblin_assets.py`,
  `python3 tools/process_spreadsheet_brute_assets.py`,
  `node tools/generate_polish_sprites.mjs`,
  `node tools/generate_audio_sfx.mjs`, or
  `node scripts/generate-retro-soundtrack.mjs`.

### Dependencies and tooling

- `package.json` uses latest Next/React/TypeScript ranges and pins Phaser to
  `4.0.0-rc.4`; only change Phaser for intentional compatibility work.
- Both `package-lock.json` and `pnpm-lock.yaml` are tracked; dependency PRs
  should keep touched lockfile ecosystems consistent and verified.
- `next lint` is unreliable here. Prefer `npm run build` and
  `npx tsc --noEmit --incremental false` for source changes.

## Suggested verification

- Markdown-only Bugbot guide change: `git diff --check origin/main...HEAD`.
- TypeScript, React, Phaser, or manifest change:
  `npx tsc --noEmit --incremental false` and `npm run build`.
- Gameplay/input/HUD/audio: run `npm run dev` and smoke test movement, Space
  firing, click firing, pickups, mute, resize, game over/restart, and F3.
- Asset generation change: run the exact owning generator/processor, then check
  manifest paths and generated dimensions.
- Dependency change: run install/audit/build commands for the changed lockfile
  ecosystem and separate known baseline audit issues from new vulnerabilities.
