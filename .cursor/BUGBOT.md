# Cursor Bugbot Review Guide

Use this repository-specific context when reviewing pull requests for the Hobgoblin Ruin Prototype.

## Project shape

- This is a Next.js App Router, React, TypeScript, and Phaser 4 RC browser game.
- `src/app/page.tsx` renders the full-screen game shell.
- `src/game/GameCanvas.tsx` is the client-only Phaser boot boundary. Keep Phaser imports inside the `useEffect` dynamic import path so server rendering does not evaluate browser-only APIs.
- Most gameplay state, rendering, input, audio, enemy behavior, pickups, and HUD logic lives in `src/game/scenes/DungeonScene.ts`.
- Dungeon generation and tile collision helpers live in `src/game/maps/startingDungeon.ts`.
- Runtime asset keys and public paths are centralized in `src/game/assets/manifest.ts`; the matching files live under `public/assets`.

## Review focus

1. **Next.js and React boundaries**
   - Preserve the `"use client"` boundary around `GameCanvas`.
   - Avoid importing Phaser, `window`, or other browser-only APIs from server components or module top-level code that can run during SSR.
   - Check metadata changes in `src/app/layout.tsx`; if OpenGraph or Twitter image paths change, verify the referenced files exist under `public` or are provided by a valid App Router metadata route.

2. **Phaser lifecycle and real-time gameplay**
   - Review scene shutdown, restarts, timers, tweens, event listeners, keyboard handlers, pointer handlers, audio nodes, and pooled objects for leaks or duplicate registration.
   - Keep frame-loop math bounded and deterministic enough for variable frame rates; preserve existing delta-time caps and cooldown semantics.
   - Check input changes against the documented controls in `README.md`.

3. **Gameplay invariants**
   - Keep tile coordinates and world coordinates distinct. Be cautious around isometric projection, depth sorting, collision bounds, and pickup/enemy spawn distances.
   - Preserve map invariants in `startingDungeon.ts`: playable tiles, walls, chasms, bridges, stairs, blocked tiles, and fallback room generation should stay reachable and coherent.
   - Watch combat and pickup changes for accidental unlimited ammo, negative health, enemy respawn loops, unreachable powerups, or score inflation.

4. **Assets and generated metadata**
   - When `assetManifest` paths, frame sizes, animation rows, or keys change, verify the corresponding PNG, JSON, WAV, or metadata file exists in `public/assets`.
   - Sprite sheet JSON and frame dimensions should match Phaser loader expectations.
   - If processing scripts under `tools/` or `scripts/` change, verify generated outputs are intentional and avoid committing transient local artifacts.

5. **Dependencies and lockfiles**
   - Dependency changes should be reflected in the appropriate lockfile generated by the selected package manager.
   - This repo currently contains both `package-lock.json` and `pnpm-lock.yaml`, so review lockfile churn carefully and make sure it matches the package manager used for the dependency change.

## Verification commands

Prefer these checks for code changes:

```bash
npm ci
npm run build
npx tsc --noEmit --incremental false
```

Known limitation: `npm run lint` currently invokes `next lint`, which is not available as an integrated subcommand in the installed Next.js 16 toolchain. Do not block a review on `npm run lint` failing for that known reason unless the lint script or Next.js version changes.

`npx tsc --noEmit` without `--incremental false` can leave `tsconfig.tsbuildinfo`; clean generated artifacts before final diffs.
